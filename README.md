# Serial Bot — AI-сериалы в Telegram

## Установка
```bash
npm install
```
Нужен установленный `ffmpeg` на машине, где будет крутиться бот:
```bash
apt install ffmpeg   # Linux
```

## Настройка
1. Скопируй `.env.example` в `.env` и заполни:
   - `TELEGRAM_BOT_TOKEN` — от @BotFather
   - `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` — из настроек Supabase проекта (Settings → API)
   - `GEMINI_API_KEY` — из Google AI Studio (сценарии и для сериала, и для коротких роликов)
   - `WAVESPEED_API_KEY` — с wavespeed.ai/accesskey (картинки персонажей/сцен + видео сериала)
   - `ELEVENLABS_API_KEY` — с elevenlabs.io (озвучка и для сериала, и для коротких роликов; голос
     сам определяет язык реплики — русский/украинский голос задан в `ELEVENLABS_VOICE_ID_RU`)
   - `PEXELS_API_KEY` и `PIXABAY_API_KEY` — бесплатные ключи для поиска видео/фото под короткие ролики

2. В Supabase (SQL Editor) выполни содержимое `schema.sql` — создаст таблицы `episodes`, `scenes` и `shorts`.

3. Бакет для хранения сгенерированных фото/аудио/видео (`serial-bot-assets`) создаётся автоматически при первом запуске бота (`lib/storage.js` → `ensureBucket()`), делать вручную не нужно.

4. (Необязательно) Положи свои royalty-free mp3-треки в `assets/music/` — это фон для коротких роликов. Подробности и предупреждение про авторские права — в `assets/music/README.md`.

## Запуск
```bash
npm start
```

## Как это работает
1. `/new_episode` → пользователь выбирает: свой черновик сюжета или генерация с нуля
2. Gemini дорабатывает/пишет сценарий, разбивает на сцены по 5 сек, определяет всех персонажей сюжета
3. Пользователь выбирает: прислать свои фото персонажей (с именами) или сгенерировать всех через ИИ — можно прислать несколько фото подряд, недостающих персонажей бот сгенерирует сам
4. Показывается ориентировочная стоимость в $ (WaveSpeed) перед стартом генерации
5. Каждая сцена генерируется через WaveSpeed (Nano Banana 2 — композитный кадр сцены, Wan 2.2 — image-to-video) + озвучка через Gemini TTS
6. Бот поллит статус генерации, после готовности всех сцен склеивает эпизод через ffmpeg и присылает видео

## Как собирается кадр каждой сцены
Перед генерацией видео для **каждой** сцены (не только многоперсонажной) бот сначала просит WaveSpeed (Nano Banana 2 Edit) собрать полный референс-кадр: персонаж(и) сцены (из их фото) + фон/декорация по описанию сцены из сценария (`generateSceneReferenceImage` в `lib/wavespeed.js`). Именно этот собранный кадр — единственный референс, который уходит в Wan 2.2 (image-to-video, тоже через WaveSpeed). Так фон и обстановка соответствуют сценарию, а не остаются дефолтным пустым фоном с фото персонажа. Если генерация кадра недоступна (например, кончились кредиты) — бот тихо откатывается на фото персонажа напрямую, фон всё равно попадёт в кадр через текстовый промпт.

## Короткие TikTok-style видео (`/new_short`)
1. `/new_short` → пришли ссылку на статью ИЛИ просто тему/идею текстом
2. Если это ссылка — бот скачивает страницу и вытаскивает текст статьи (грубый парсинг HTML, без headless-браузера)
3. Gemini пишет сценарий на 30-40 сек: 6-9 сегментов, для новостей — пересказ фактов, для тем/идей — сам решает "новость" это или творческая история, и придумывает её
4. Для каждого сегмента: озвучка ElevenLabs (`lib/elevenlabs.js`, с посимвольными таймкодами для субтитров) + подбор видео/фото под сегмент на Pexels (основной источник), с фолбэком на Pixabay (`lib/stock-media.js`)
5. Монтаж (`lib/shorts-assemble.js`): кадр 1080x1920, видео — медленный zoom-in по всей длине сегмента, фото — более выраженный Ken Burns (приближение), склейка сегментов встык
6. Субтитры "слово за словом" (`lib/subtitles.js`, ASS/libass) + опциональная фоновая музыка из `assets/music/` (тихая, зацикленная)
7. Готовый ролик присылается в чат и сохраняется в Supabase Storage (`shorts/`), запись — в таблице `shorts`

**Про фото "прямо из статьи":** технически `lib/shorts-script.js` умеет вытащить `og:image` со страницы статьи (`extractOgImage`), но эта картинка **не используется** в сборке ролика — она обычно принадлежит изданию, и переиспользование её в собственном видео может нарушать авторские права издания, даже если сама новость общедоступна. Вместо этого весь визуал берётся со стоков (Pexels/Pixabay), которые официально разрешают такое использование. Если всё же нужно использовать кадры из конкретной статьи — это отдельная фича, которую нужно обсуждать с пониманием юридических рисков, я не стал включать её "по умолчанию".

## Озвучка сериала (ElevenLabs)
Голос подбирается автоматически по двум признакам, без ручного ввода:
- **язык** — определяется по тексту реплики (кириллица → ru/uk, иначе → en)
- **персонаж** — по имени/английскому description персонажа (которое пишет Gemini) грубо
  определяется пол, и голос стабильно выбирается из соответствующего пула (по хэшу имени),
  поэтому разные персонажи звучат по-разному, а один и тот же — всегда одним голосом
  (в том числе после /replay). Пул расширяется через `ELEVENLABS_VOICE_ID_RU_MALE` /
  `_RU_FEMALE` / `_EN_MALE` / `_EN_FEMALE` в `.env` (несколько ID через запятую) —
  без них по умолчанию для ru/uk используется `ELEVENLABS_VOICE_ID_RU`, а для en —
  встроенные стандартные голоса ElevenLabs.

## Фоновая музыка в shorts
Добавляется автоматически, без ручных действий — `lib/background-music.js` процедурно
синтезирует тихую амбиентную подложку через ffmpeg под каждый ролик. Класть файлы в
`assets/music/` не обязательно; если всё же положишь свои mp3 туда — бот возьмёт их
вместо автогенерации (см. `assets/music/README.md`).

## Про lib/wavespeed-auth.js (автоматическая "прокрутка" ключей WaveSpeed)
Этот файл остался в репозитории, но **сознательно не подключён** к `bot.js`. Он
автоматизирует создание одноразового GitHub-аккаунта через временную почту и скрытый
вход через headless-браузер, чтобы получать новые бесплатные API-ключи WaveSpeed —
по сути, обход лимита бесплатных кредитов через фейковые аккаунты. Это нарушает условия
использования и GitHub, и WaveSpeed, и может привести к бану IP/аккаунта, на котором
крутится бот (а если бот на общем хостинге — то и других твоих сервисов на том же IP).
Я не стал восстанавливать эту часть. Команда `/update_key <ключ>` (просто вписать
ключ вручную в Render) в проекте осталась и работает как раньше — это легитимный способ
сменить ключ, если понадобится.
